## معرفی

CoreLink یک سیستم کنترل خانگی است که روی میکروکنترلر ESP32-S3 اجرا می‌شود. این سیستم یک Access Point وایرلس راه‌اندازی می‌کند و از طریق یک داشبورد وب امکان کنترل ۴ رله، مشاهده وضعیت سیستم، و تنظیم زمان‌بندی خودکار را فراهم می‌کند.

**قابلیت‌های اصلی:**

- کنترل ۴ رله با قابلیت روشن/خاموش دستی
- زمان‌بندی خودکار برای هر رله (ساعت شروع و پایان)
- مشاهده زنده وضعیت حافظه، uptime، و منابع سیستم
- تنظیم شبکه Wi-Fi از طریق داشبورد
- به‌روزرسانی firmware و فایل‌های وب از طریق OTA
- اتصال همزمان به عنوان AP و Station (اتصال به روتر خانگی با NAT)
- همگام‌سازی زمان از طریق NTP

---

## سخت‌افزار مورد نیاز

| قطعه | مشخصات |
|------|---------|
| میکروکنترلر | ESP32-S3 WROOM-1 (8MB Flash، 2MB PSRAM) |
| LED وضعیت | WS2812 RGB — GPIO 48 |
| دکمه ریست | تاکتیل — GPIO 14 (Pull-up داخلی) |
| رله ۱ | GPIO 15 |
| رله ۲ | GPIO 16 |
| رله ۳ | GPIO 17 |
| رله ۴ | GPIO 18 |

> **نکته:** خروجی GPIO برای رله‌ها به صورت معکوس (Active Low) است. سطح HIGH = رله خاموش، سطح LOW = رله روشن.

## راهنمای کاربر

### اتصال اولیه

۱. برد را برق‌دار کنید. LED آبی/سبز چشمک می‌زند.
۲. در تنظیمات Wi-Fi دستگاه خود، شبکه‌ای با نام **`ESP32-S3-AP`** را پیدا کنید.
۳. با رمز عبور **`12345678`** وصل شوید.
۴. مرورگر خود را باز کنید و به آدرس **`http://192.168.4.1`** بروید.

> در اکثر گوشی‌ها بلافاصله پس از اتصال، صفحه Captive Portal به صورت خودکار باز می‌شود.

---

### داشبورد وب

داشبورد سه بخش اصلی دارد که از منوی کناری قابل دسترسی هستند:

| بخش | توضیح |
|-----|-------|
| **Device Control** | کنترل رله‌ها و مشاهده وضعیت سیستم |
| **Settings** | تنظیمات شبکه، زمان، و دستگاه |
| **Firmware Update** | بارگذاری firmware یا فایل‌های وب جدید |

نقطه رنگی در گوشه پایین سایدبار وضعیت اتصال را نشان می‌دهد:
- 🟢 سبز: دستگاه آنلاین و در دسترس
- 🔴 قرمز: ارتباط قطع شده

---

### کنترل رله‌ها

هر رله یک کارت مجزا دارد که شامل موارد زیر است:

**کنترل دستی:**
- دکمه **ON** — رله را فوری روشن می‌کند
- دکمه **OFF** — رله را فوری خاموش می‌کند

**زمان‌بندی خودکار:**

۱. ساعت **Start** و **Stop** را وارد کنید (فرمت ۲۴ ساعته)
۲. کلید زمان‌بندی را فعال کنید
۳. دکمه **Apply** را بزنید

> زمان‌بندی هر ۵ ثانیه بررسی می‌شود. اگر ساعت شروع و پایان یکسان باشند، رله هرگز فعال نمی‌شود.  
> برای زمان‌بندی که از نیمه‌شب رد می‌شود (مثلاً ۲۲:۰۰ تا ۰۶:۰۰) نیز پشتیبانی می‌شود.

**Emergency Stop:**

دکمه ⬛ STOP در پایین صفحه، تمام ۴ رله را فوری خاموش می‌کند و تمام زمان‌بندی‌ها را غیرفعال می‌کند. LED قرمز ثابت روشن می‌ماند تا نشان دهد حالت اضطراری فعال است.

### تنظیمات شبکه

از منوی **Settings** → **Network Configuration**:

| فیلد | توضیح |
|------|-------|
| Wi-Fi SSID | نام شبکه‌ای که دستگاه به عنوان AP broadcast می‌کند |
| Current Password | رمز فعلی (برای تغییر رمز الزامی است) |
| New Password | رمز جدید (حداقل ۸ کاراکتر) |
| Channel | کانال Wi-Fi (۱ تا ۱۳) |
| Max Connections | حداکثر تعداد کلاینت‌های همزمان (۱ تا ۱۰) |
| Use DHCP | اگر غیرفعال شود، IP استاتیک تنظیم می‌شود |

**تنظیمات Station (اتصال به روتر خانگی):**

از بخش **Station Configuration** می‌توانید SSID و رمز روتر خود را وارد کنید. در این حالت دستگاه همزمان هم AP است هم به اینترنت وصل می‌شود و NAT فعال می‌شود تا کلاینت‌های AP هم به اینترنت دسترسی داشته باشند.

> پس از ذخیره تنظیماتی که نیاز به اعمال دارند، دستگاه به صورت خودکار ریستارت می‌شود.

---

### به‌روزرسانی firmware

از منوی **Firmware Update**:

**به‌روزرسانی Firmware:**
۱. فایل `.bin` جدید firmware را انتخاب کنید
۲. دکمه **Upload & Reboot** را بزنید
۳. پیشرفت آپلود را دنبال کنید
۴. دستگاه خودکار ریستارت می‌شود (حدود ۳۰ ثانیه)

**به‌روزرسانی Web Files:**
۱. فایل `.bin` LittleFS را انتخاب کنید (خروجی `idf.py build`)
۲. مانند بالا آپلود کنید

> هر دو فایل می‌توانند همزمان در یک مرحله آپلود شوند.  
> سیستم OTA دو پارتیشن دارد. اگر firmware جدید خراب باشد، با فشردن دکمه ریست به نسخه قبلی برمی‌گردد.

---

### ریست کارخانه

**از طریق داشبورد:**  
Settings → Device → ⚠ Reset — تمام تنظیمات NVS پاک و دستگاه ریستارت می‌شود.

**از طریق دکمه سخت‌افزاری:**  
دکمه GPIO 14 را **۱۰ ثانیه** نگه دارید تا ریست کارخانه انجام شود.

### ماژول‌های firmware

#### `main.c` — ترتیب راه‌اندازی

نقطه ورود برنامه. ترتیب فراخوانی اهمیت دارد:

```
nvs_flash_init()
  └── reset_button_init()
      └── esp_netif_init() + esp_event_loop_create_default()
          └── relay_init()
              └── led_status_init()
                  └── wifi_init()
                      └── filesystem_init()
                          └── http_server_start()
```

یک task نظارتی (`monitor_task`) هر ۲ ثانیه زمان فعلی و تعداد کلاینت‌های متصل را لاگ می‌کند.

---

#### `wifi.c` — مدیریت شبکه

دستگاه در حالت **APSTA** کار می‌کند: همزمان Access Point و Station است.

**منطق DNS:**
- وقتی STA متصل **نیست**: DNS server فعال است تا تمام درخواست‌ها را به IP اکسس پوینت هدایت کند (captive portal).
- وقتی STA متصل **شد**: DNS server متوقف می‌شود و DNS روتر خانگی به کلاینت‌های AP منتقل می‌شود.

**منطق retry اتصال STA:**
اگر اتصال به روتر قطع شود، با تاخیر نمایی (exponential backoff) تلاش مجدد می‌شود. حداکثر تاخیر ۳۰ ثانیه است. پس از رسیدن به `sta_max_retry`، دستگاه در حالت AP-only می‌ماند.

**تنظیمات ذخیره‌شده در NVS (`wifi_config_store`):**

| کلید | نوع | توضیح |
|------|-----|-------|
| `ssid` | string | نام AP |
| `password` | string | رمز AP |
| `channel` | u8 | کانال Wi-Fi |
| `max_conn` | u8 | حداکثر کلاینت |
| `ip` / `gateway` / `netmask` / `dns` | string | تنظیمات IP استاتیک |
| `dhcp` | u8 | فعال/غیرفعال بودن DHCP |
| `sta_ssid` / `sta_pass` | string | اطلاعات روتر خانگی |
| `sta_retry` | u8 | حداکثر تعداد تلاش مجدد |

---

#### `relay.c` — کنترل رله

چهار رله روی GPIOهای 15 تا 18 تعریف شده‌اند. خروجی **Active Low** است (LOW = روشن).

**ساختار داده هر رله:**

```c
typedef struct {
    bool             is_on;      // وضعیت فعلی
    relay_schedule_t schedule;   // زمان‌بندی (ساعت شروع، ساعت پایان، فعال/غیرفعال)
    gpio_num_t       gpio;       // شماره GPIO
} relay_state_t;
```

**task زمان‌بندی** هر ۵ ثانیه اجرا می‌شود. منطق بررسی از minute-of-day استفاده می‌کند تا از مشکل عبور از نیمه‌شب جلوگیری کند:

```c
// اگر start < stop: بازه عادی
// اگر start > stop: بازه از نیمه‌شب رد می‌شود
```

وضعیت هر رله و زمان‌بندی آن در NVS (namespace: `relay_cfg`) ذخیره می‌شود تا پس از قطع برق حفظ شود.

---

#### `led_status.c` — LED وضعیت

LED RGB روی GPIO 48 از طریق درایور `led_strip` با پروتکل RMT کنترل می‌شود.

**سیستم بیت‌ماسک:**

```c
// خطاها (چشمک قرمز سریع — هر ۲۵۰ms)
LED_ERR_WIFI       = (1 << 0)
LED_ERR_FILESYSTEM = (1 << 1)
LED_ERR_HEAP       = (1 << 2)
LED_ERR_HTTP       = (1 << 3)
LED_ERR_ESTOP      = (1 << 4)

// هشدارها (چشمک زرد کند — هر ۱۰۰۰ms)
LED_WARN_HEAP      = (1 << 0)
```

**منطق اولویت:**
- اگر هر خطایی وجود داشته باشد → قرمز چشمک‌زن
- در غیر این صورت اگر هشداری وجود داشته باشد → زرد چشمک‌زن
- در غیر این صورت → سبز ثابت (حالت نرمال)

یک mutex از دسترسی همزمان task های مختلف به متغیرهای وضعیت جلوگیری می‌کند.

---

#### `http_server.c` — سرور HTTP

از `esp_http_server` با `uri_match_wildcard` استفاده می‌شود. فایل‌های استاتیک از LittleFS خوانده و chunk-by-chunk ارسال می‌شوند.

**ترتیب ثبت endpoint ها اهمیت دارد** — endpoint های دقیق‌تر باید قبل از wildcard `/*` ثبت شوند.

---

#### `ota_handler.c` — به‌روزرسانی OTA

دو endpoint مجزا وجود دارد:

**`/api/ota/firmware`**: از `esp_ota_ops` استفاده می‌کند. داده را به پارتیشن `ota_1` (یا `ota_0` بسته به حالت فعلی) می‌نویسد، سپس boot partition را تغییر می‌دهد و ریستارت می‌کند.

**`/api/ota/webfs`**: پارتیشن LittleFS را پاک کرده و داده جدید را مستقیم با `esp_partition_write` می‌نویسد. سپس ریستارت می‌کند تا LittleFS دوباره mount شود.

داده در هر دو حالت در بافرهای ۴KB دریافت و نوشته می‌شود.

---

#### `time_handler.c` — مدیریت زمان

**اولویت منابع زمان:**
1. اگر STA متصل باشد: SNTP از ۳ سرور NTP (قابل تنظیم)
2. اگر NTP در دسترس نباشد: مرورگر ساعت خود را از طریق `POST /api/time` ارسال می‌کند

تنظیمات timezone و NTP server ها در NVS (namespace: `time_cfg`) ذخیره می‌شوند.

---

#### `system_monitor.c` — نظارت سیستم

اطلاعات زیر را جمع‌آوری می‌کند و در پاسخ `GET /api/status` برمی‌گرداند:

- Heap کلی، آزاد، استفاده‌شده، حداقل تاریخی
- Internal RAM (IRAM): کلی، آزاد، درصد استفاده
- PSRAM: کلی، آزاد، درصد استفاده
- اندازه Flash، تعداد هسته‌های CPU، uptime به ثانیه

`system_monitor_check_health()` آستانه‌های هشدار را بررسی می‌کند:
- بالای ۷۰٪ استفاده از IRAM → هشدار LED زرد
- بالای ۸۵٪ → خطا LED قرمز

### معماری فرانت‌اند

فرانت‌اند کاملاً با Vanilla JS/HTML/CSS نوشته شده و هیچ dependency خارجی ندارد. تمام فایل‌ها در پارتیشن LittleFS ذخیره می‌شوند.

**`core/api.js`**  
تمام درخواست‌های HTTP از اینجا می‌گذرند. `API.BASE` از `window.location.origin` تنظیم می‌شود تا با هر IP کار کند.

**`core/toast.js` / `core/modal.js`**  
اعلان‌های کوتاه (toast) و دیالوگ تأیید (modal) که در تمام صفحات مشترک هستند.

**`pages/control.js`**  
هر ثانیه یک بار `GET /api/status` را صدا می‌زند و telemetry را به‌روز می‌کند. ۴ کارت رله را مدیریت می‌کند.

**`pages/settings.js`**  
تنظیمات شبکه، Station، و زمان را بارگذاری و ذخیره می‌کند. در صورت نیاز به ریستارت، یک modal اطلاعات اتصال مجدد را نمایش می‌دهد.

**`pages/update.js`**  
فایل‌های OTA را از طریق `XMLHttpRequest` آپلود می‌کند (برای نمایش progress bar).

## مرجع API

| Endpoint | Method | توضیح |
|----------|--------|-------|
| `/` | GET | صفحه اصلی داشبورد |
| `/api/status` | GET | وضعیت سیستم (heap، uptime، LED، STA) |
| `/api/relay` | POST | کنترل رله: `{"relay": 1, "state": true}` |
| `/api/relay/state` | GET | وضعیت تمام رله‌ها به همراه زمان‌بندی |
| `/api/relay/schedule` | POST | تنظیم زمان‌بندی رله |
| `/api/settings` | GET | خواندن تنظیمات شبکه AP |
| `/api/settings` | POST | ذخیره تنظیمات شبکه AP |
| `/api/sta-settings` | GET | خواندن تنظیمات Station |
| `/api/sta-settings` | POST | ذخیره تنظیمات Station |
| `/api/time` | POST | تنظیم زمان از مرورگر: `{"hour":14,"minute":30,"second":0}` |
| `/api/time-settings` | GET/POST | تنظیمات NTP و timezone |
| `/api/led` | POST | کنترل LED: `{"enabled": true}` |
| `/api/ota/firmware` | POST | آپلود firmware جدید (binary) |
| `/api/ota/webfs` | POST | آپلود فایل‌های وب (binary) |
| `/api/estop` | POST | خاموش کردن اضطراری تمام رله‌ها |
| `/api/reboot` | POST | ریستارت دستگاه |
| `/api/factory` | POST | ریست کارخانه |

## LED وضعیت

| رفتار LED | معنا |
|-----------|------|
| 🟢 سبز ثابت | حالت نرمال، همه چیز سالم |
